# Design Baseline — docs-guide-site (기준 설계 문서)

> 이 그룹의 **요구사항·설계 결정의 단일 기준**. append-only — 항목은 지우지 않고 상태(Active/Superseded)만 바꾼다.
>
> **ID 범위:** `REQ-0xx`·`ADR-0xx` 는 **이 그룹 안에서만** 번호를 매긴다. 지적 ID(FEA-01 등)는 검수 보고의 번호를 그대로 쓴다.

## 0. 질의 수준 (Autonomy Level)

- [ ] **적극(Thorough)**
- [ ] **보통(Balanced)**
- [x] **간략(Lean)** — 사용자가 범위를 정해 승인했다. 지적이 코드와 어긋나면 코드대로 쓰고 보고한다.

선택: **간략** · 선택일: 2026-10-22 · 변경 이력: (없음)

## 1. 목적 / 배경

main `e4806f6` 위에 생성된 HTML 가이드 사이트(허브 + 19편)를 2차 검수한 결과 42건(HIGH 2 포함)이 나왔다.
사용자가 생성물 커밋을 승인했고, 원본을 먼저 커밋한 뒤 지적대로 고친다.

|---|---|---|---|---|---|
| REQ-001 | 2026-10-22 | "1번으로 지적 전부 고쳐줘" | 지적 42건을 코드 근거를 다시 열어 확인한 뒤 고친다. 같은 오류 재발을 막는 최소 내용 계약 테스트 4종 | Active | ADR-001·002, ledger 전체 |

## 3. 설계 결정 (append-only)

| ADR-ID | 날짜 | 결정 | 상태 |
|---|---|---|---|
| ADR-001 | 2026-10-22 | **HTML 19편은 한 틀로 다시 쓴다.** 생성 원본은 기능 8편이 같은 문장을 공유해 같은 결함이 복제돼 있었다. 줄 단위 서식·고정 Mermaid·CDN 실패 안내를 공통 틀로 맞추고 내용만 페이지별로 쓴다. 생성 스크립트는 저장소에 넣지 않는다 — 계약 테스트가 결과를 지킨다 | Active |
| ADR-002 | 2026-10-22 | **"CODE-VERIFIED GUIDE" 라벨을 뗀다.** 검증 사실(기준 커밋·대조 테스트)은 꼬리말에 적는다 — 기준 main `e4806f6`, API 표·설정 표·Mermaid 버전·허브 링크는 `tests/test_docs_guide_site.py` 가 대조 | Active |

## 4. 불가침 제약

- C-1: 코드 동작 불변(docstring·주석만).
- C-2: `docs/review/`·`.env`·logs 는 커밋하지 않는다.
- C-3: CRP 기록은 append-only — 다른 그룹의 기존 행을 고치지 않는다.
