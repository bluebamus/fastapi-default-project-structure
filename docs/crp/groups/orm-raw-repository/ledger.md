| F-039 | LOW | AR-008 / REQ-010 — 종료 과정의 로그가 유실되지 않는다 | Fix | **Open** | 미착수 — **설계 결정 필요**(아래 해법 후보) | **`uvicorn main:app` CLI 경로에서는 ADR-022 의 신호 핸들러가 효력이 없다.** uvicorn 은 `serve()` 에서 `capture_signals()` 로 **먼저** 원래 핸들러를 스냅샷한 뒤, 그 안쪽 `_serve()` 에서 `config.load()` 로 앱을 import 한다(`uvicorn/server.py:68-77`). 즉 우리 `configure_logging()` 은 스냅샷보다 **나중에** 실행되므로, 우리가 건 핸들러는 종료 시 복구되는 `SIG_DFL` 에 덮인다. `python main.py` 는 앱 import 가 `uvicorn.run()` 보다 먼저라 영향이 없다(그래서 F-038 수정이 그 경로에서만 관측된다). 실측 잔여 손실은 앱 종료 로그 **마지막 3줄**이다 — `[dispose_engine] Disposing …` 이후의 dispose 완료 · `[shutdown] … 자원 해제 완료` · `[log-lifecycle] stop 시작/완료`. uvicorn 자신의 로그는 CLI 경로에서 우리 queue 를 타지 않으므로 온전히 남는다(ADR-020). → 해법 후보: lifespan 종료 **맨 끝에서 queue 를 flush**(정지 아님)한다. stdlib 의 `QueueListener._monitor` 가 record 마다 `task_done()` 을 부르므로 `queue.join()` 이 "전부 처리될 때까지" 를 정확히 표현하고, `asyncio.wait_for(asyncio.to_thread(...))` 로 예산을 준다. CLI 경로에서는 lifespan 이후 우리 queue 로 나가는 로그가 없으므로 이걸로 잔여가 사라진다. **다만 ADR-018 의 "lifespan 은 listener 를 건드리지 않는다" 계약과 shutdown 예산에 영향이 있어 별도 결정이 필요하다.** |
