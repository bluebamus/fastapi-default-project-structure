## 검사하지 않은 것 (범위 밖 명시)

정직한 보고를 위해, 이번 작업이 **확인하지 않은** 것을 적는다.

- **부하·성능**: 커넥션 풀 크기, 큐 로그 처리량, 집계 쿼리의 대용량 실행 계획을 측정하지 않았다.
- **복제 실환경**: `DB_REPLICATION_ENABLED=true` 의 라우팅 판정은 단위 테스트로 검증했으나,
  실제 replica 를 띄워 복제 지연 하에서의 read-after-write 를 관측하지는 않았다.
- **Celery 워커 실행**: 태스크 정의와 세션 컨텍스트는 검사했지만 워커를 기동해 돌리지 않았다.
- **QUICKSTART 2단계의 단일 MySQL `docker run` 경로**: 통합 테스트용 `compose.test.yaml`
  (포트 3308)만 실행 확인했다.
- **Scalar UI 실렌더링**: OpenAPI 문서의 **구조**는 규칙 테스트로 검증했으나, 브라우저에서
  Scalar 가 어떻게 그리는지는 보지 않았다.

## 2026-09-21 — 의존성 취약점 (ADR-032 측정 중 드러남)

- **남은 권고 21건 / 4패키지.** `anyio` 3건은 ADR-032 로 해소했으나, 같은 측정에서
  ~~`starlette 0.46.2`(PYSEC-2026-161·248·249·1941·1942·2280·2281, fix 최대 1.3.1)~~,
  ~~`sqladmin 0.24.0`(PYSEC-2026-3073·3922, fix 0.27.1)~~, ~~`aiomysql 0.2.0`(PYSEC-2026-1110,
  fix 0.3.0)~~, ~~`pytest 8.4.2`(PYSEC-2026-1845, fix 9.0.3)~~ 가 함께 잡혔다. 이번 범위가
  아니라 손대지 않았다 — starlette 은 0.46 → 1.3 으로 **메이저를 넘는 상향**이라 FastAPI
  호환과 `TestClient` 하네스를 함께 봐야 하고, 독립 커밋·독립 검수가 맞다.
  **해소 (2026-09-21, ADR-033)**: `pytest` 는 9.1.1 로, 함께 묶인 `pytest-asyncio` 는
  1.4.0 으로 올렸다. 상향 후 재측정한 `pip-audit` 출력은 **19건 / 3패키지**
  (starlette · sqladmin · aiomysql)이고 pytest 는 목록에서 사라졌다. 21 → 19 로 2가
  줄어든 것은 `requires-python >= 3.13` 때문에 lock 이 해석을 갈라 같은 권고가 두 줄로
  나오기 때문이다 — 고유 권고는 pytest 1건이 빠진 것이 맞다.
  **해소 (2026-09-21, ADR-034)**: 남은 세 패키지를 한 커밋으로 `starlette 1.6.0` ·
  `sqladmin 0.32.0` · `aiomysql 0.3.2` 로 올렸다. 쪼갤 수 없었던 이유는 `sqladmin 0.24.0` 이
  `starlette` 를 버전 제약 없이 요구해 1.x 를 막지도, 지원 선언하지도 않기 때문이다
  (`sqladmin 0.31.0` 부터 `starlette>=0.50,<2.0` 명시). 상향 후 `pip-audit` 은 **0건**이다.
  `uv lock` 에서 움직인 패키지는 이 셋뿐(82개 중 3개)이고, `-m "not mysql"` 577 passed ·
  `-m mysql --mysql-required` 8 passed(MySQL 8.4 실제 컨테이너)로 기준선이 유지됐다.
- **게이트가 이것을 보지 못한다.** `scripts/review_gate.py` 에는 의존성 감사 단계가 없다.
  그래서 21건이 초록불 아래에서 조용히 쌓였다. 감사 단계를 게이트에 넣을지는 정책 판단이며,
  넣는다면 기존 권고가 전부 실패로 잡히므로 상향과 **같은 작업으로 묶어야** 한다.
- 재현: `uv run --with pip-audit python -m pip_audit`
