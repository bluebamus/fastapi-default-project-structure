설계·워크플로우 시퀀스 다이어그램

기동, 요청, 인증, 종료, Celery의 프로세스와 자원 경계를 한 페이지에서 비교합니다.

1. 프로세스 기동

sequenceDiagram participant U as Uvicorn participant C as config.py participant W as 명시적 feature import participant A as FastAPI app participant L as lifespan/resources participant R as Redis participant D as DB U->>C: import main:app C-->>U: 검증·캐시된 settings U->>W: 기능 배선 준비 W->>A: routers/models/admin/hooks U->>L: lifespan enter L->>R: connect + ping + version L->>D: 개발 DDL/ready 준비 L-->>U: serve 가능

2. API 요청

sequenceDiagram Client->>Middleware: HTTP Middleware->>FastAPI: context FastAPI->>Policy: DI + auth Policy->>Service: Principal + DTO Service->>Repository: use case Repository->>Database: query/flush Database-->>Repository: result Repository-->>Service: data Service-->>FastAPI: response data FastAPI->>Database: validate DTO then commit FastAPI-->>Client: JSON

3. 인증과 refresh 회전

sequenceDiagram Client->>Auth: credentials Auth->>Redis: rate limit Auth->>DB: password verify Auth-->>Client: access + refresh Client->>Auth: refresh token Auth->>Redis: GETDEL/rotate family Redis-->>Auth: accepted once Auth-->>Client: new token pair

4. 종료와 요청 밖 작업

flowchart LR Signal --> Stop[새 요청 중지] Stop --> Drain[접속 로그 background drain] Drain --> Redis[Redis close] Redis --> DB[DB engines dispose] DB --> Logs[log listener stop] Task[Celery task] --> WorkerLoop[worker event loop] WorkerLoop --> BgSession[background DB session] BgSession --> WorkerShutdown[worker 전용 cleanup]

FastAPI lifespan은 Celery worker에서 실행되지 않으므로 worker는 자기 event loop와 DB engine 정리를 소유합니다.

5. 확장 시 도식 유지 규칙

  • 새 외부 자원은 생성 주체, 공유 범위, readiness, 종료 순서를 함께 명시합니다.
  • 요청 session을 background task로 넘기지 않습니다.
  • 인증 경계를 추가하면 성공뿐 아니라 401/403/429/503과 폐기 흐름도 갱신합니다.
  • 새 데이터 경로는 commit 소유자와 rollback 지점을 한 곳으로 유지합니다.
