PROJECT GUIDE

API 요청 처리

요청이 미들웨어, 접근 수준 의존성, View, Service, DB 세션을 지나 응답이 되는 순서입니다.

허브 부팅 설계 API 설정 요청 인증 기능 개발 테스트 운영

도식은 고정 버전 Mermaid CDN을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

미들웨어 순서

바깥에서 안쪽으로 unhandled_exception_middleware → UserInfoMiddleware → CORS 입니다. main.py 가 CORS, UserInfo 순으로 등록한 뒤 예외 미들웨어를 마지막에 등록하므로 예외 미들웨어가 가장 바깥입니다.

  • unhandled_exception_middleware: 처리기가 없는 예외를 500 JSON 으로 끝내 로그 1번·keep-alive 유지. DEBUG=true 면 다시 던집니다(개발 중 traceback 확인).
  • UserInfoMiddleware: client IP(TRUSTED_PROXY_HOPS 기준)·User-Agent·경로·메서드·쿼리(민감 키는 ***)·Referer·세션 쿠키 값을 모으고, 응답 뒤 상태 코드·소요 시간·user_id 를 더해 저장 태스크를 제출합니다. 저장 실패는 응답에 영향을 주지 않습니다.
  • CORS: CORS_* 설정대로 동작합니다.

세션과 트랜잭션

  • 기능 라우터는 조회에 get_read_only_db_session(쓰기 시도 시 즉시 실패, 라우터가 켜져 있으면 replica), 쓰기에 get_writer_db_session(첫 쿼리부터 primary)을 씁니다. get_routed_db_session 은 승인된 특수 경로용이며 현재 기능 라우터는 쓰지 않습니다.
  • 쓰기 핸들러(View)가 응답 DTO 를 먼저 검증한 뒤 await service.commit() 을 정확히 한 번 부르고 반환합니다. 세션은 의존성(get_writer_db_session)이 열고 닫으며, 커밋 전에 예외가 나면 세션 종료가 롤백합니다. Repository·Dependency 는 커밋하지 않습니다(tests/test_write_dto_before_commit.py, 검수 게이트 INV-2).
  • 요청 밖(접속 로그 저장·Celery 태스크)은 background_db_session 을 쓰고 그 안에서 직접 커밋합니다.

오류 응답

  • AppException 계열은 상태 코드대로 {error_code, message, detail} 응답(4xx 는 WARNING, 5xx 는 ERROR 로그).
  • 입력 오류는 422 VALIDATION_ERROR, Starlette HTTP 예외는 HTTP_<code>.
  • Redis 연결·타임아웃 오류는 503 SERVICE_UNAVAILABLE. Redis 를 쓰는 요청만 해당합니다.
  • 그 밖의 예외는 500 이고 DEBUG=true 에서만 가려진 예외 문자열을 detail 에 싣습니다.
  • 로그와 접속 로그를 잇는 기준은 경로·메서드·시각·user_id 입니다(요청마다 붙이는 별도 식별자는 없습니다).
