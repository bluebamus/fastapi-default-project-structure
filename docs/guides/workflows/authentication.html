CODE-VERIFIED GUIDE

API JWT 인증

가입·로그인·보호 API·refresh 회전·로그아웃의 경계와 실패 원칙을 설명합니다.

허브부팅설계 API요청인증 기능개발운영

인증 모델

API는 Bearer JWT를 사용하고, 짧은 수명의 access token과 서버 저장소에서 상태를 관리하는 refresh token을 분리합니다. 관리자 화면의 쿠키 세션은 별도 경계이므로 서로 대체하지 않습니다.

보안 의도와 확장

  • refresh token 회전은 탈취 토큰의 재사용 창을 줄입니다. 저장소 오류를 성공으로 간주하지 않습니다.
  • 로그인·가입은 공개 쓰기이지만 rate limit 대상입니다.
  • 라우트 접근 수준과 리소스 소유권을 분리해 owner/superuser 정책을 재사용합니다.
  • 외부 IdP를 추가할 때도 내부 Principal과 접근 수준 계약은 유지합니다.
