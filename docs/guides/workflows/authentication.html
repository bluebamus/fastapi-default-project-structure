PROJECT GUIDE

API JWT 인증

가입·로그인·보호 API·refresh 회전·로그아웃의 경계와 실패 규칙입니다.

허브 부팅 설계 API 설정 요청 인증 기능 개발 테스트 운영

도식은 고정 버전 Mermaid CDN을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

인증 모델

API 는 Bearer JWT 를 씁니다. access 토큰(기본 15분)에는 sub·username·su(슈퍼유저 여부)가 실리고, refresh 토큰(기본 7일)에는 jti·fam(계열)이 실려 Redis 의 RefreshTokenStore 가 회전을 기록합니다. 관리 화면(/admin)의 Redis 서버 세션은 별도 경계이며 API 를 인증하지 않습니다.

알아야 할 한계와 규칙

  • access 토큰은 폐기 목록이 없어 만료(ACCESS_TOKEN_EXPIRE_MINUTES, 기본 15분)까지 유효합니다. su 는 발급 시점 값이라 강등·비활성화·삭제 뒤에도 그동안 이전 권한이 남습니다.
  • 보호 라우트는 토큰 클레임만 봅니다(DB 조회 없음). /api/v1/auth/me 만 DB 에서 사용자를 다시 읽어 삭제·비활성 사용자를 401 로 돌려보냅니다.
  • 비활성화·삭제는 그 사용자의 refresh 계열을 모두 폐기하고(관리 세션도 함께), 강등은 관리 세션만 끊습니다.
  • 레이트 리밋은 login(IP+사용자명 5회·IP 20회, 60초 창)과 register(IP 5회, 3600초 창)에만 있습니다. refresh·logout 에는 없습니다.
  • 레이트 리밋·회전·폐기는 Redis 에 있어 Redis 연결 오류면 해당 요청은 503 입니다(fail-closed).
  • 슈퍼유저 전용 라우트도 토큰이 없거나 틀리면 403 이 아니라 401 입니다.
