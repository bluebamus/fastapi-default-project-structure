PROJECT GUIDE

환경 설정 레퍼런스

config.py 의 Settings 9종·필드 69개와 기동 시 검사 규칙입니다.

허브 부팅 설계 API 설정 요청 인증 기능 개발 테스트 운영

도식은 고정 버전 Mermaid CDN을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

값이 들어오는 순서

설정을 읽는 곳은 config.py 하나입니다. 우선순위는 프로세스 환경 변수 → 작업 디렉터리의 .env → 코드 기본값이고, .env.example 은 복사용 견본일 뿐 자동으로 읽지 않습니다. 리스트는 JSON 배열(CORS_ALLOW_ORIGINS=["https://example.com"])로 씁니다. Settings 는 import 때 한 번 만들어 캐시하므로 실행 중 .env 를 바꿔도 반영되지 않습니다.

기동 시 검사

  • 타입·validator 오류(예: CORS * + 자격 증명, 로그 포맷 자리표시자 누락)는 Settings 생성 때 실패합니다.
  • .env 가 없으면 ENV·ACCESS_TOKEN_SECRET_KEY·REFRESH_TOKEN_SECRET_KEY·SESSION_SECRET_KEY·MYSQL_HOST·MYSQL_USER·MYSQL_PASSWORD·MYSQL_DATABASE 8개가 환경 변수로 와야 합니다.
  • 예전 설정 ADMIN 이 환경 변수나 .env 에 있으면 거부합니다(ADMIN_DISABLED 로 바뀌었고 뜻이 반대).
  • test 를 뺀 모든 ENV: 비밀 키 3종·MYSQL_PASSWORD 가 예시 값(change-this 포함·your- 시작·빈 값)이면, 비밀 키가 32자 미만이면, access 와 refresh 키가 같으면 거부합니다. REDIS_PASSWORD 는 값이 있을 때만 봅니다.
  • ENV=staging/production 만: DEBUG=true, LOG_LEVEL=DEBUG 를 거부합니다.
  • 위반은 모아서 RuntimeError 하나로 올리고 메시지에는 설정 이름만 담습니다(값은 싣지 않음).

설정을 추가할 때

  1. config.py 에 타입·설명·안전한 기본값으로 필드를 추가하고 그 값을 읽는 코드도 함께 넣습니다(정의만 있는 필드는 tests/core/test_settings_usage.py 가 실패).
  2. .env.example 에 같은 이름을 적습니다(tests/core/test_settings_contract.py 가 양방향 대조).
  3. 비밀 값이면 LOG_SECRET_SETTINGS 와 validate_deployment_safety() 검사 대상에, 파일 없이도 꼭 와야 하면 REQUIRED_WITHOUT_ENV_FILE 에 넣습니다.
  4. 이 표에 행을 더합니다(tests/test_docs_guide_site.py 가 빠진 필드를 잡습니다).
