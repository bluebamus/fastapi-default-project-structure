환경 설정 레퍼런스

.env.example과 설정 모델을 기준으로 값의 유입과 검증 책임을 설명합니다.

허브부팅설계 API요청인증 기능개발운영

사용 원칙

설정의 단일 진입점은 config.py이며 환경 변수 이름과 예시는 .env.example에서 확인합니다. 운영 비밀은 저장소에 커밋하지 않고 비밀 관리 시스템에서 주입합니다.

예제 환경 변수

변수예제 값인접 설명
PROJECT_NAMEFastAPI Project프로젝트 이름 (Scalar 문서 제목, 관리자 페이지 제목에 표시). 코드 기본값과 같다.
VERSION0.1.0애플리케이션 버전 (/health 응답의 version, OpenAPI info.version). 코드 기본값과 같다.
DEBUGtrueRedis 연결 확인은 DEBUG 와 무관하게 항상 startup 조건이다.
ADMIN_DISABLEDfalse예전에 false(끔)였다면 그 줄을 지우고 ADMIN_DISABLED=true 를, true(켬)였다면 그 줄만 지운다.
ENVdevelopment`your-` 시작·빈 값)이거나 32자 미만이거나 access==refresh 이면 test 외 모든 ENV 에서 기동을 거부한다.
SERVER_HOST0.0.0.0관리 화면을 쓰지 않으면 위 ADMIN_DISABLED=true 로 아예 없앤다.
SERVER_PORT8000
TIME_ZONEAsia/Seoul예시: Asia/Seoul, UTC, America/New_York
MYSQL_HOSTlocalhostMySQL 서버 호스트 (IP 또는 도메인)
MYSQL_PORT3306MySQL 서버 포트
MYSQL_USERrootMySQL 접속 사용자명
MYSQL_PASSWORDchange-this-mysql-passwordMySQL 접속 비밀번호 (예시 값·빈 값이면 test 외 모든 ENV 에서 기동을 거부한다)
MYSQL_DATABASEfastapi_db사용할 데이터베이스 이름
DB_ROUTER_ENABLEDfalse구현: app/core/db/router.py
DB_REPLICATION_ENABLEDfalse- false: 라우터를 켜도 replica 가 없으므로 읽기도 primary 로 나간다.
DB_READ_STICKY_AFTER_WRITEtruefalse 로 두면 읽기 분산은 늘어나지만 read-after-write 일관성을 잃는다.
MYSQL_REPLICA_HOSTS[]예: MYSQL_REPLICA_HOSTS=["10.0.0.11", "replica-b.example.com:3307"]
MYSQL_REPLICA_PORT3306포트를 명시하지 않은 replica 에 적용할 기본 포트
REDIS_HOSTlocalhostRedis 서버 호스트
REDIS_PORT6379Redis 서버 포트
REDIS_DB0Redis 데이터베이스 번호 (0-15)
REDIS_PASSWORDRedis 비밀번호 (설정하지 않으면 인증 없이 접속 — 비워 두는 것도 정상 구성이다)
CORS_ALLOW_ORIGINS["*"]특정 Origin만 허용: ["http://localhost:3000", "https://example.com"]
CORS_ALLOW_CREDENTIALSfalse자격 증명(쿠키, Authorization 헤더) 허용 여부
CORS_ALLOW_METHODS["GET", "POST", "PUT", "DELETE", …허용할 HTTP 메서드 (JSON 배열 형식)
CORS_ALLOW_HEADERS["*"]허용할 HTTP 헤더 (JSON 배열 형식)
CORS_MAX_AGE600Preflight 요청 캐시 시간 (초)
LOG_CONSOLE_ENABLEDtrue콘솔이 꺼지면 기동 때 stderr 에 경고 한 줄이 나온다(파일도 꺼져 있으면 앱 로그는 버려진다).
LOG_SQL_ECHO_ENABLEDfalse찍는다. 쿼리를 눈으로 봐야 할 때만 잠깐 켠다. 운영에서는 절대 켜지 말 것.
LOG_FILE_ENABLEDfalse그때는 파일을 끄고 콘솔(stdout) + 수집기/logrotate 를 쓴다.
ACCESS_LOG_ENABLEDtrue(background 세션 풀, 동시 256건 초과분은 버린다)
ACCESS_LOG_RETENTION_DAYS365beat 를 띄워야 동작한다: uv run celery -A app.celery.app beat --loglevel=INFO
TRUSTED_PROXY_HOPS0로그인 레이트 리밋(API·/admin)이 전체 사용자를 한 사람으로 취급한다(한 명의 실패가 모두를 막는다).
SESSION_COOKIE_NAMEsession세션 쿠키 이름
SESSION_SECRET_KEYchange-this-session-secret-key생성 방법: uv run python -c "import secrets; print(secrets.token_urlsafe(48))"
ACCESS_TOKEN_SECRET_KEYchange-this-access-token-secret-keyuv run python -c "import secrets; print(secrets.token_urlsafe(48))"
REFRESH_TOKEN_SECRET_KEYchange-this-refresh-token-secret-key
ACCESS_TOKEN_EXPIRE_MINUTES15Access Token 만료 시간 (분, 기본값: 15분). access 는 서버에서 폐기할 수 없으므로 짧게 둔다.
REFRESH_TOKEN_EXPIRE_DAYS7Refresh Token 만료 시간 (일, 기본값: 7일). 회전 기록·폐기 표시(Redis)도 같은 TTL 을 쓴다.

확장 방법

  1. 설정 필드를 타입과 안전한 기본값으로 추가합니다.
  2. .env.example에는 비밀이 아닌 예시와 설명을 추가합니다.
  3. 서로 의존하는 값은 설정 검증 단계에서 빠르게 실패시킵니다.
  4. 배포 매니페스트와 테스트 fixture를 함께 갱신합니다.
