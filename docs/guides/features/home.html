PROJECT GUIDE

접속 로그 기능(home)

ACCESS_LOG_ENABLED 일 때 제외 경로·확장자가 아닌 요청의 접속 정보를 저장하고, 슈퍼유저 조회 API·보존 삭제 태스크를 제공합니다.

허브 부팅 설계 API 설정 요청 인증 기능 개발 테스트 운영

도식은 고정 버전 Mermaid CDN을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

목적과 책임

  • UserInfoMiddleware(core)가 모은 정보를 이 기능의 HomeAccessLogSink 가 background_db_session 으로 저장하고 직접 커밋합니다. sink 는 app/features/home/__init__.py 가 import 될 때 등록됩니다.
  • 조회 API 는 전부 SuperuserRequired 이고 read_only 세션을 씁니다(요청 경로의 쓰기 없음).
  • tasks.py 의 home.purge_expired_access_logs 가 매일 03:30(TIME_ZONE) beat 로 돌며 ACCESS_LOG_RETENTION_DAYS(기본 365, 0 이면 삭제 안 함)보다 오래된 로그를 지웁니다. home.aggregate_access_stats 는 통계 집계 예시 태스크입니다. beat 를 띄우지 않으면 로그가 계속 쌓입니다.
핵심 패턴: core 미들웨어 → 기능 sink 등록 훅, 요청 밖 세션

트랜잭션 경계: 쓰기 핸들러(View)가 응답 DTO 를 먼저 검증한 뒤 await service.commit() 을 정확히 한 번 부르고 반환합니다. 세션은 의존성(get_writer_db_session)이 열고 닫으며, 커밋 전에 예외가 나면 세션 종료가 롤백합니다. Repository·Dependency 는 커밋하지 않습니다(tests/test_write_dto_before_commit.py, 검수 게이트 INV-2).
