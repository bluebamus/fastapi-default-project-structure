12. 테스트

개발·확장의 세부 주제입니다. 목적·책임·운영 및 확장 시 지켜야 할 계약을 설명합니다.

12. 테스트

12.1 위치와 실행

  • 기능 테스트: app/features/<name>/tests/test_*.py. core 계약·배선·교차 기능: tests/. 실제 프로세스·DB: tests/integration/.
  • 실행 명령·마커·CI 는 README.
  • 엔드포인트 테스트는 in-memory SQLite(aiosqlite, StaticPool)로 get_writer_db_session· get_read_only_db_session 을 둘 다 app.dependency_overrides 로 바꾸고 커밋 횟수를 셉니다 (app/features/catalog/tests/test_endpoint.py). 한쪽만 바꾸면 다른 경로가 실제 MySQL 로 새어 나갑니다. 오버라이드는 테스트 끝에 복원합니다.
  • httpx.ASGITransport 요청만으로는 lifespan 이 실행되지 않습니다. lifespan 을 검증하려면 컨텍스트에 실제로 진입하거나(app.router.lifespan_context) 실제 프로세스를 띄웁니다.
  • 라우트 목록은 app.openapi()["paths"] 로 얻습니다 — app.routes 는 하위 라우터를 평탄화하지 않습니다.
  • SQLite 통과는 MySQL 방언·Decimal 정밀도·시간대·잠금의 근거가 아닙니다. MySQL 전용 동작은 @pytest.mark.mysql 로 tests/integration/ 에 두고, mysql_session_maker fixture 가 테스트마다 스키마를 다시 만듭니다.
  • 전수 통합(tests/e2e/, uv run python -m pytest -m e2e)은 실제 MySQL 복제·Redis·uvicorn·Celery·Chromium 위에서 돕니다(README "E2E 전수 통합"). 새 API·관리 뷰·태스크·Redis 키를 더하면 여기에도 칸이 생깁니다. tests/e2e/test_zz_inventory.py 가 실제 앱에서 operation·관리 뷰·Celery 태스크·Redis 접두어를 뽑아, 각 칸을 실행한 테스트(cover(...))나 N/A 사유가 없으면 실패합니다.
  • 새 operation: tests/e2e/test_b_api_matrix.py 의 SPECS 에 칸별 요청(정상·검증 오류·권한 부족·없음)을 더한다. 미인증·잘못된 메서드·접근 정책 칸은 선언에서 자동으로 만든다. 해당 없는 칸은 문자열(사유)로 적는다.
  • 새 관리 뷰: tests/e2e/test_d_admin.py 의 VIEWS 에 테이블·생성 폼·수정 필드를 더한다.
  • 새 태스크·beat 일정·Redis 키 접두어: 그것을 실제로 쓰는 시나리오를 test_c_flows.py 에 두고 cover(...) 한다.

12.3 커버리지 하한

하한은 pyproject.toml 의 [tool.coverage.report] fail_under 한 곳이고 기본값은 0(하한 없음 — 측정·리포트만)입니다. CI 는 --cov=app --cov-branch --cov-report=term-missing 으로 수치를 출력합니다. CI·게이트 명령줄에 --cov-fail-under 를 두지 않습니다 (tests/test_coverage_contract.py 가 지킨다). 올리고 싶으면:

  1. uv run python -m pytest -m "not mysql" --cov=app --cov-branch --cov-report=term-missing 로 지금 수치를 잰다.
  2. 그보다 조금 낮은 값을 fail_under 에 적는다(흔들림 여유). 다른 곳은 고치지 않는다.
  3. 테스트가 쌓이면 같은 방법으로 조금씩 올린다.
