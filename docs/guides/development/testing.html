PROJECT GUIDE

테스트와 검증

로컬·CI 에서 돌리는 명령과 각 테스트 층이 무엇을 보는지 정리합니다.

허브 부팅 설계 API 설정 요청 인증 기능 개발 테스트 운영

도식은 고정 버전 Mermaid CDN을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

기본 명령

REDIS_HOST=127.0.0.1 REDIS_PORT=6379 uv run python -m pytest -m "not mysql"   # CI gate 와 같은 집합
uv run ruff check . && uv run ruff format --check .
uv run mypy .
uv run python -m scripts.review_gate --fast                                   # pytest 제외 구조 검사

docker compose -f compose.test.yaml up -d --wait                              # MySQL 8.4(3308) + Redis
uv run python -m pytest -m mysql --mysql-required                             # 닿지 못하면 skip 이 아니라 실패
uv run python -m pytest -m e2e -rsxX                                          # E2E, 스택은 하네스가 띄운다
  • REDIS_HOST·REDIS_PORT 를 둘 다 주지 않으면 실제 uvicorn 수명 테스트(tests/integration/test_uvicorn_lifecycle.py)가 실패합니다. 주었는데 닿지 않으면 skip 됩니다.
  • pytest 콘솔 스크립트 대신 python -m pytest 를 씁니다. pyproject.toml 이 DEBUG=true·ENV=test 로 실행합니다.
  • skip 은 통과가 아닙니다. CI 는 skipped·xfailed·xpassed 가 있으면 실패합니다. 마커는 mysql·e2e 를 씁니다(e2e 는 마커식에 없으면 deselect).

포트 충돌·E2E 하네스·검수 게이트 표·CI job 은 README 테스트·검수·CI 가 정본입니다.

변경 완료 조건

성공 경로뿐 아니라 잘못된 입력, 미인증, 권한 부족, 없음, 충돌을 검증합니다. 외부 서비스가 필요한 테스트를 돌리지 못했다면 결과에 명시하고 CI(mysql·e2e job)에서 확인합니다.
