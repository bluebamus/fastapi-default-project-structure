PROJECT GUIDE

부팅과 첫 실행

설정 검사부터 lifespan, readiness, 종료까지 실제 기동 순서와 첫 실행 준비물을 정리합니다.

허브 부팅 설계 API 설정 요청 인증 기능 개발 테스트 운영

도식은 고정 버전 Mermaid CDN을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

두 단계로 나뉜다

설정 검사는 config 모듈을 import 하는 순간 실행됩니다. config.py 끝의 validate_env_source·validate_no_legacy_admin·validate_deployment_safety 가 위반을 RuntimeError 로 올리므로 앱 조립과 lifespan 에 도달하지 못합니다.

lifespan 은 app/core/resources.py 의 manage_application_resources() 를 열 뿐이고, 여기서 Redis PING 과 버전 확인(6.2 이상), 모델 import, DEBUG=true 일 때만 개발용 테이블 생성(create_all, MySQL 접속)을 합니다. DEBUG=false 면 기동 중에 DB 에 접속하지 않습니다. /ready 는 lifespan 과 별개인 엔드포인트입니다.

첫 실행 준비

  1. uv sync 로 잠금 파일 기준 의존성을 설치합니다.
  2. cp .env.example .env 후 uv run python -c "import secrets; print(secrets.token_urlsafe(48))" 를 세 번 실행해 ACCESS_TOKEN_SECRET_KEY·REFRESH_TOKEN_SECRET_KEY·SESSION_SECRET_KEY 에 서로 다른 값(32자 이상)을 넣고, MYSQL_PASSWORD 에 실제 비밀번호를 넣습니다. 예시 값·빈 값이면 개발 환경에서도 기동을 거부합니다.
  3. Redis(6.2 이상)를 띄웁니다. DEBUG 와 무관한 필수 기동 조건입니다.
  4. DEBUG=true(기본값)면 MySQL 이 떠 있어야 합니다(개발용 테이블 생성). 운영과 같은 경로는 DEBUG=false + uv run alembic upgrade head 입니다.
  5. uv run python main.py(또는 uv run uvicorn main:app --reload)로 실행합니다. --lifespan off 는 쓰지 않습니다.
  6. GET /health(생존)와 GET /ready(DB·Redis 준비)를 따로 확인합니다.
  7. 관리 화면과 슈퍼유저 API 를 쓰려면 uv run python -m scripts.create_superuser --username admin --email admin@example.com 으로 첫 슈퍼유저를 만듭니다.

단계별 명령·조합표(Redis 만으로 배선 확인 등)의 정본은 README 빠른 시작 입니다.

실패를 읽는 법

  • 설정 오류는 메시지에 고칠 설정 이름이 나옵니다. .env 가 없으면 필수 8개(ENV·비밀 키 3종·MYSQL_HOST/USER/PASSWORD/DATABASE)가 환경 변수로 와야 합니다. 이 검사와 예전 설정 ADMIN 검사는 ENV=test 에서 건너뜁니다.
  • Redis 에 닿지 못하거나 6.2 미만이면 기동이 실패합니다. 기동 뒤 Redis 연결 오류는 Redis 를 쓰는 요청(레이트 리밋·refresh·logout·토큰과 관리 세션 폐기, /ready)만 503 이 되고, Redis 를 쓰지 않는 조회는 그대로 응답합니다.
  • /ready 는 SELECT 1 과 PING 만 봅니다. 마이그레이션 누락·스키마 불일치는 /ready 가 200 이어도 그 테이블을 쓰는 요청에서 500 으로 드러납니다.
  • 뷰에 접근 수준 선언이 빠지면 AccessPolicyError 로 기동이 멈춥니다(위반 목록 포함).
  • 종료는 background drain(5초) → Redis close(5초) → DB dispose(10초) → 로그 큐 flush(2초) 순서이고 시간 제한은 단계마다 따로 걸립니다. SHUTDOWN_TOTAL_TIMEOUT_SECONDS(20초)는 정의만 있고 전체를 강제하지 않아 lifespan 정리만 최대 약 22초, listener 정지까지 약 29초입니다(진행 중 요청 대기는 별도). 컨테이너 종료 유예는 이보다 길게 둡니다.
