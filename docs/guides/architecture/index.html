PROJECT GUIDE

아키텍처

기능 경계, 계층 책임, 의존 방향과 조립 방식을 코드 기준으로 설명합니다.

허브 부팅 설계 API 설정 요청 인증 기능 개발 테스트 운영

도식은 고정 버전 Mermaid CDN을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

조립 방식

main.py 가 미들웨어·예외 처리기·문서를 구성하고 기능 라우터 8개를 include_router(prefix="/api") 로 한 줄씩 조립합니다. 관리 화면은 ADMIN_DISABLED 가 아니면 app/features/admin.py 의 register_admin() 이 ADMIN_VIEWS 를 등록하고 /admin 을 마운트합니다. 마지막 줄 AccessPolicyGuard().verify(app) 가 모든 뷰의 접근 수준 선언을 검사합니다.

반대로 모델과 Celery 태스크는 디렉터리 규칙으로 자동 탐색합니다. app/core/db/models_registry.py 가 app/features/<name>/models/models.py 와 app/features/<name>/tasks.py 를 찾아 metadata 등록(Alembic·개발용 테이블 생성)과 워커 include 를 만듭니다. 그래서 main.py 에서 라우터를 빼도 폴더가 남아 있으면 모델은 여전히 테이블 생성·Alembic 대상입니다.

  • View 는 HTTP 변환·접근 수준 선언·응답 DTO 검증·커밋을 맡고, SQL 이나 세션을 직접 다루지 않습니다.
  • Dependency 는 세션(get_read_only_db_session/get_writer_db_session)을 고르고 Service 를 조립합니다. 커밋하지 않습니다.
  • Service 는 업무 규칙과 OwnershipPolicy 검사를 하고 Repository 를 씁니다. Repository 는 영속성만 다루고 커밋하지 않습니다.
  • 트랜잭션 경계: 쓰기 핸들러(View)가 응답 DTO 를 먼저 검증한 뒤 await service.commit() 을 정확히 한 번 부르고 반환합니다. 세션은 의존성(get_writer_db_session)이 열고 닫으며, 커밋 전에 예외가 나면 세션 종료가 롤백합니다. Repository·Dependency 는 커밋하지 않습니다(tests/test_write_dto_before_commit.py, 검수 게이트 INV-2).

의존 규칙

  • features → core → utils. core 는 기능을 import 하지 않습니다.
  • 기능끼리는 import 하지 않습니다. 예외는 auth → user(모델·UserRepository) 하나이고 tests/core/test_layering.py 가 AST 로 강제합니다.
  • 여러 기능이 쓰는 협력 객체(해시·토큰·refresh 저장소·소유권 규칙)의 provider 는 app/core/security/dependencies.py 에 둡니다.
  • core 가 기능 동작을 써야 하면 등록 훅을 씁니다(예: home 이 import 시점에 접속 로그 sink 를 등록).
