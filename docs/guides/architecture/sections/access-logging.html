10. 접속 로그 미들웨어

UserInfoMiddleware(app/core/middlewares/user_info_middleware.py)가 요청마다 정보를 모으고, 응답을 받은 뒤 access_log_tasks.spawn() 으로 저장 태스크를 제출합니다. core 는 저장 방법을 모르고, access_log_sink.get_access_log_sink() 에 등록된 sink 에 위임합니다. home 이 import 시점에 HomeAccessLogSink 를 등록하며, 이 sink 는 background_db_session()(별도 풀)으로 저장하고 직접 커밋합니다.

설정 기본값
ACCESS_LOG_ENABLED true
ACCESS_LOG_EXCLUDE_PATHS ["/health", "/docs", "/redoc", "/openapi.json", "/favicon.ico"] (정확히 일치)
ACCESS_LOG_EXCLUDE_EXTENSIONS [".css", ".js", ".ico", ".png", ".jpg", ".jpeg", ".gif", ".svg"] (접미사)
ACCESS_LOG_SENSITIVE_QUERY_KEYS ["password", "token", "access_token", "refresh_token", "secret", "api_key", "code"] (대소문자 무시, 값을 *** 로 저장)
ACCESS_LOG_RETENTION_DAYS 365 (보존 일수. 0 이면 지우지 않는다, 음수는 기동 시 검증 오류 — 아래 "보존")
TRUSTED_PROXY_HOPS 0 (앞단 신뢰 프록시 수 — 0 이면 전달 헤더를 보지 않는다. 프록시 뒤 배포는 단 수만큼 — 0 이면 전원이 프록시 IP 하나로 보여 접속 로그·로그인 레이트 리밋이 한 사람으로 취급하고, 크게 잡으면 IP 위조)
  • 수집: ip_address(아래 IP 결정 규칙), forwarded_for·real_ip(원본 헤더 — 감사용), user_agent 와 파싱 결과(os_name·os_version·browser_name·browser_version·device_type (mobile/tablet/desktop/other)·device_brand·device_model·is_bot), request_path, request_method, query_string(민감 키 값은 ***), referer, accept_language, session_id(설정 SESSION_COOKIE_NAME 쿠키의 값), user_id(request.state.user_id — 인증 의존성 get_current_principal 이 라우트 처리 중에 채우므로 미들웨어가 응답 뒤에 읽는다. 익명·401 요청은 NULL, §11.1), response_status, response_time_ms.
  • IP 결정 — app/core/middlewares/client_ip.py 의 ClientIPResolver 가 정하고, 미들웨어는 생성자로 받습니다(setup_user_info_middleware 가 설정에서 한 번 만든다, service-hardening ADR-006·ADR-021). TRUSTED_PROXY_HOPS=0(기본)이면 직접 피어 주소만 씁니다. N 이면 X-Forwarded-For 의 오른쪽에서 N번째 값(신뢰 프록시 N단이 덧붙인 값)이고, 목록이 N개보다 짧거나 값이 IP 가 아니면 직접 피어로 물러납니다. X-Real-IP 는 hops>0 이고 X-Forwarded-For 가 없을 때만 봅니다. uvicorn --forwarded-allow-ips 와 같은 모델이며, 실제 프록시 단수보다 크게 잡으면 다시 위조할 수 있게 됩니다.
  • 길이 — 문자열은 저장 직전 home 기능(fit_to_columns)이 UserAccessLog 컬럼 길이로 자릅니다. 길이는 모델 컬럼에서 읽습니다(숫자를 두 번 적지 않는다). MySQL strict 모드에서 길이 초과 INSERT 가 실패해 기록이 조용히 버려지던 경로를 막습니다.
  • user_access_logs 테이블의 country·country_code·city 컬럼은 채우는 코드가 없습니다. 인덱스: created_at·ip_address·os_name·browser_name·device_type·country·session_id·user_id.
  • session_id 쿠키 값·referer·forwarded_for(X-Forwarded-For)·real_ip 는 원문 그대로 저장합니다 — 사용자 결정으로 유지합니다(log-redaction ADR-004). 조회 API 는 슈퍼유저 전용입니다.
  • 보존(security-ops-hardening ADR-002·ADR-003) — Celery beat 가 매일 03:30(TIME_ZONE 기준) home.purge_expired_access_logs 를 실행해 created_at < 지금(UTC) − ACCESS_LOG_RETENTION_DAYS 일 인 행을 지웁니다(정확히 N일 전 행은 남는다). 정책은 AccessLogRetentionService(보존 일수·시계 주입), 쿼리는 UserAccessLogRepository.delete_created_before — created_at 인덱스로 id 를 최대 5,000개 고른 뒤 DELETE ... WHERE id IN (...) 하고 배치마다 커밋합니다(긴 잠금·거대 트랜잭션 방지, MySQL·SQLite 공통 쿼리). 0 이면 쿼리 없이 끝납니다. beat 를 띄우지 않으면 아무것도 지워지지 않습니다(§13).
  • X-Forwarded-For 는 클라이언트가 위조할 수 있으므로 신뢰 프록시 홉 수(TRUSTED_PROXY_HOPS) 밖의 값은 믿지 않습니다. 이전에는 맨 왼쪽 값을 무조건 믿었습니다 — 기본값 0 은 이 동작을 바꾼 것이니 프록시 뒤 배포는 홉 수를 설정해야 실제 클라이언트 IP 가 기록됩니다.
  • BackgroundTaskRunner 는 동시 256개가 상한이고 넘치면 버리고 dropped 를 올립니다. 비핵심 로그용이라 결제·발송 같은 업무 저장을 이 러너에 넣지 않습니다. 종료 시 drain 합니다(§8).
  • 저장 실패는 요청에 영향을 주지 않고 ERROR 로그만 남깁니다. 제출 시점은 call_next 가 응답 객체를 돌려준 뒤이며, 클라이언트가 본문을 다 받았다는 보장은 아닙니다. call_next 가 예외로 끝난 요청은 status 500 으로 기록한 뒤 예외를 그대로 다시 던집니다(바깥 500 처리는 그대로 — service-hardening ADR-007).
  • 조회 API 는 /api/v1/home/access-logs 계열 5개(전부 읽기 세션)이고, 예시 Celery 태스크 home.aggregate_access_stats 가 통계를 집계합니다.
