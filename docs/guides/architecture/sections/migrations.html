# migrations/env.py
fileConfig(config.config_file_name, disable_existing_loggers=False)   # 앱 로거를 끄지 않는다

    db_settings.ALEMBIC_URL.render_as_string(hide_password=False).replace("%", "%%"),
)
  • URL: ALEMBIC_DATABASE_URL 이 있으면 그 값을 make_url 로 읽은 것, 없으면 primary URL 의 드라이버만 mysql+pymysql 로 바꾼 것. 마이그레이션은 항상 primary 에서 실행합니다. Alembic Config 는 ConfigParser 라 % 를 보간으로 읽으므로 %% 로 바꿔 넘깁니다(퍼센트 인코딩된 비밀번호 대비).
  • revision 체인(단일 head, CI 가 확인): f4adf0ae24ea(baseline — 기존 5개 테이블) → b2f1a9c0d3e4 (users.hashed_password) → c3d5e7f9a1b2(catalog_products) → d4e6f8a0b2c3(sales_orders) → e5f7a9b1c4d5(sales_daily_snapshots) → a7c9e1f3b5d6(시각 컬럼 전부 MySQL DATETIME(6) + 기존 값 KST→UTC 변환, SQLite 는 no-op — service-hardening ADR-010). 배포 전: 이 리비전은 기존 MySQL 값을 모두 +09:00 으로 가정합니다 — 다른 시간대였다면 적용 전에 리비전의 _LEGACY_OFFSET 을 바꾸고, 값을 고쳐 쓰므로 적용 전에 백업합니다.
  • env.py 는 app/core/models/types.py 의 compare_type(MySQL UTCDateTime 의 소수 초 자릿수 비교 — 기본 비교는 DATETIME 과 DATETIME(6) 을 같다고 본다)과 render_item(autogenerate 가 앱 import 없는 sa.DateTime().with_variant(mysql.DATETIME(fsp=6), "mysql") 로 쓰게)을 넘깁니다.
  • Alembic 은 lifespan 에 들어가지 않으므로 Redis 확인을 하지 않습니다. 서버 기동은 upgrade 를 하지 않습니다.
  • DEBUG=true 의 create_all 은 migration 결함을 가립니다(예전 baseline 이 테이블 4개를 빠뜨렸는데 개발 환경에서는 보이지 않았습니다). 그래서 빈 DB 에서 head 까지 올리고 모델과 비교하는 테스트가 있습니다: tests/core/test_migration_chain.py(SQLite), tests/integration/test_mysql_raw_sql.py(MySQL 8.4 — upgrade → downgrade → 재-upgrade).
  • 작성 절차는 DEVELOPMENT §8.
