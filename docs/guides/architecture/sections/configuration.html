6. 설정

아키텍처의 세부 주제입니다. 목적·책임·운영 및 확장 시 지켜야 할 계약을 설명합니다.

6. 설정

6.1 로딩 규칙

  • config.py 의 10개 BaseSettings 는 각각 env_file=".env", extra="ignore" 로 자기 필드를 읽습니다. 우선순위는 프로세스 환경 변수 → 작업 디렉터리의 .env → 코드 기본값입니다.
  • get_*_settings() 는 @lru_cache 이고, 파일 끝의 app_settings = get_app_settings() 등이 import 시점에 전역 객체를 만듭니다. 실행 중 .env 를 바꿔도 반영되지 않습니다. 테스트에서 캐시만 비워도 이미 가져간 전역 참조는 그대로이므로 새 프로세스나 monkeypatch 로 확인합니다.
  • 타입 오류·validator 위반은 config import 자체를 실패시켜 lifespan 전에 기동을 막습니다. validator: 복제 설정 모순·replica 주소 형식(DatabaseSettings), CORS_ALLOW_ORIGINS=["*"] + CORS_ALLOW_CREDENTIALS=true(CORSSettings), 관리 세션 미사용 만료 > 절대 만료(SessionSettings).
  • 전역 객체를 만든 뒤 파일 끝에서 설정 검사 세 개가 차례로 돕니다. 모두 RuntimeError 로 config import 를 실패시키고, 메시지에는 설정 이름만 나옵니다. ENV=test 는 모두 건너뜁니다(pytest 가 지정). 1. validate_env_source() — 출처(ADR-045 ①). .env 가 없으면 ENV·비밀 키 3종·MYSQL_HOST/USER/PASSWORD/DATABASE (REQUIRED_WITHOUT_ENV_FILE)가 환경 변수로 모두 있어야 합니다. 컨테이너 주입은 통과하고, 아무것도 없으면 멈춥니다. 2. validate_no_legacy_admin() — 예전 이름(admin-login ADR-005). ADMIN(true=켬)은 뜻이 뒤집힌 ADMIN_DISABLED(true=끔)로 바뀌었으므로, 환경 변수나 .env 에 ADMIN 이 남아 있으면(대소문자 무시) 조용히 무시하지 않고 멈춥니다. 3. validate_deployment_safety() — 내용. 위반을 모두 모아 한 번에 알립니다.
    • test 외 모든 ENV(ADR-027·030·045 ②): ACCESS_TOKEN_SECRET_KEY·REFRESH_TOKEN_SECRET_KEY·SESSION_SECRET_KEY·MYSQL_PASSWORD 가 예시 값(change-this 포함·your- 시작·빈 값), 비밀 키 3종이 32자 미만, access 와 refresh 가 같음. REDIS_PASSWORD 는 값이 있을 때만 예시 값인지 봅니다 — 비밀번호 없는 사설망 Redis 가 정당한 구성이라 빈 값은 통과합니다.
    • staging/production 만(ADR-028): DEBUG=true, LOG_LEVEL=DEBUG. 관리 화면을 켠 배포는 막지 않습니다 — 슈퍼유저 로그인이 붙어 ADR-045 ③ 의 확인 플래그를 없앴습니다(admin-login ADR-004). 예시 값 판정은 is_placeholder_secret() 하나가 맡습니다(tests/core/test_deployment_safety.py). SERVER_HOST 등 그 밖의 운영 조합은 막지 않습니다(C-8).
  • 환경 변수를 직접 읽는 곳은 config.py 뿐입니다(tests/core/test_settings_contract.py).

6.2 설정 클래스와 소비 지점

전역 객체 소비 지점
timezone_settings 로그 시각(TzFormatter), 모델 시간 기본값, Celery timezone, 스냅샷 generated_at
app_settings FastAPI 메타데이터, DEBUG(문서·DDL·로그 레벨 기본값·500 detail·reload), ADMIN_DISABLED(관리 화면 마운트 여부), ENV(로그 구성·관리 세션 쿠키 Secure), SERVER_HOST/PORT
db_settings DSN·라우팅·replica(session.py), ALEMBIC_URL(migrations/env.py)
cors_settings CustomCORSMiddleware.configure_cors()
log_settings build_dictconfig() — LOG_LEVEL·LOG_APP_LEVELS·LOG_CONSOLE_LEVEL·LOG_SQL_ECHO_ENABLED, console_formatter_kwargs()·file_formatter_kwargs()(LOG_CONSOLE_FORMAT·LOG_FILE_FORMAT·LOG_DATE_FORMAT), console_enabled()(LOG_CONSOLE_ENABLED), setup.attach_log_files()(LOG_FILE_*·LOG_DIR·LOG_MAX_SIZE_MB·LOG_RETENTION_DAYS) — §9.2
middleware_settings UserInfoMiddleware 활성·제외 규칙
redis_settings startup ping client(REDIS_URL), Celery broker/backend
jwt_settings app/core/security/dependencies.py 의 provider(TokenService·RefreshTokenStore 생성), app/features/auth/dependencies/auth_dependencies.py 의 레이트 리밋 한도
session_settings SESSION_SECRET_KEY — 관리 세션 ID → Redis 키 HMAC(new_admin_session_store, §12). ADMIN_SESSION_MAX_AGE_SECONDS·ADMIN_SESSION_IDLE_SECONDS — 관리 세션 절대·미사용 만료(§12, 기본값은 README 세션·토큰 만료). SESSION_COOKIE_NAME — 접속 로그의 session_id 기록(§10, 인증에 쓰지 않음).

읽는 코드가 없는 필드는 tests/core/test_settings_usage.py 가 막습니다 — 예외 목록은 없습니다. 메일(SMTP_*)·업로드(UPLOAD_*)·SESSION_EXPIRE_SECONDS(config-cleanup)와 API_VERSION·ApiSettings (config-cleanup-2)는 읽는 코드가 없어 지웠고, 옛 .env 줄은 extra="ignore" 로 무시됩니다.
