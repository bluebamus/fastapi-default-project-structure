13. Celery

아키텍처의 세부 주제입니다. 목적·책임·운영 및 확장 시 지켜야 할 계약을 설명합니다.

13. Celery

  • 앱: app/celery/app.py 의 celery_app — broker·backend 모두 REDIS_URL, include=iter_task_modules(), JSON 직렬화, timezone=TIME_ZONE, enable_utc=True(내부 시각은 UTC, crontab 은 TIME_ZONE 으로 해석), 빈 beat_schedule.
  • 주기 작업(beat) — 중앙 앱은 빈 beat_schedule 만 두고, 기능의 tasks.py 가 import 될 때 자기 항목을 celery_app.conf.beat_schedule[...] 에 더합니다(security-ops-hardening ADR-003 — 중앙이 기능을 import 하지 않는 태스크 자동 발견과 같은 철학). beat 도 기동 시 include 모듈을 import 하므로(loader.init_worker) 그 등록이 보입니다. 현재 항목은 home.purge_expired_access_logs(매일 03:30 TIME_ZONE, §10 보존) 하나입니다. 실행: uv run python -m celery -A app.celery.app:celery_app beat --loglevel=INFO — worker 와 별도 프로세스 하나만 띄웁니다 (beat 가 둘이면 같은 작업이 두 번 실행된다). beat 는 실행 시각을 celerybeat-schedule 파일에 기록하므로 쓰기 가능한 작업 디렉터리가 필요합니다.
  • 태스크는 각 기능의 app/features/<name>/tasks.py 에 둡니다(예: app/features/home/tasks.py 의 home.aggregate_access_stats). include 는 모델 등록과 같은 기능 패키지 탐색(app/core/db/models_registry.py 의 iter_task_modules())이 만듭니다 — tasks.py 가 있는 기능만 들어가고, 탐색은 find_spec 으로 존재만 확인해 태스크 모듈을 import 하지 않습니다(태스크 모듈은 celery_app 을 import 하므로 앱 생성 중 import 하면 순환이 된다). app/celery 는 기능을 import 하지 않으므로 기능 디렉터리를 지우면 그 태스크도 include 에서 함께 빠지고 worker 는 깨지지 않습니다(service-hardening ADR-012, tests/core/test_celery_app.py 가 AST 로 고정). 같은 모듈이 import_all_models() 로 기능 모델을 모두 등록합니다(worker 진입점이 이 모듈이다).
  • 태스크 본문의 서비스 조립은 그 기능의 provider 함수(세션을 인자로 받는 일반 함수, 예: build_user_access_log_service(session))를 재사용합니다 — HTTP provider 도 같은 함수를 부릅니다.
  • FastAPI 는 worker·beat 를 띄우지 않습니다. 실행 예: uv run python -m celery -A app.celery.app:celery_app worker --loglevel=INFO (Redis 필요, 이 문서 작성 시점에 worker 기동은 검증하지 않음).
  • 태스크 함수는 동기이고 내부 코루틴은 run_async()(app/celery/task.py)로 실행합니다. 프로세스당 영속 event loop 를 재사용합니다 — aiomysql 연결은 만든 루프에 묶이는데, 매번 asyncio.run() 으로 루프를 닫으면 두 번째 태스크가 Event loop is closed 로 실패했습니다. 태스크 안 DB 는 background_db_session().
  • 수명(app/celery/lifecycle.py, AR-010): worker_process_init → restart_log_listener()(fork 로 사라진 listener 스레드 복구). worker_process_shutdown → 루프가 살아 있는 동안 dispose_engine()(10초) → shutdown_asyncgens() → loop.close() → 루프 참조 제거. FastAPI lifespan 과 소유권이 섞이지 않습니다.
  • 요청의 세션·Service·Request 객체를 태스크 인자로 넘기지 않습니다 — JSON 직렬화 가능한 id·값만 넘기고 태스크가 자기 세션을 엽니다. 재시도·중복 처리는 태스크마다 정합니다.
