PROJECT GUIDE

배포와 운영

배포 전 설정, 마이그레이션, 첫 관리자, readiness, 관측, 장애 대응을 연결한 운영 요약입니다.

허브 부팅 설계 API 설정 요청 인증 기능 개발 테스트 운영

도식은 고정 버전 Mermaid CDN을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

배포 전 필수 확인

  • ENV=production(또는 staging)을 명시합니다. 이때 DEBUG=true·LOG_LEVEL=DEBUG 면 기동을 거부하고, 관리 세션 쿠키에 Secure 가 붙습니다.
  • 비밀 키 3종(서로 다르게, 32자 이상)·MYSQL_PASSWORD(쓰면 REDIS_PASSWORD)를 비밀 저장소에서 주입합니다. .env 없이 주입하면 필수 8개가 모두 있어야 합니다.
  • 접속 정보는 URL 이 아니라 개별 키 MYSQL_HOST/PORT/USER/PASSWORD/DATABASE·REDIS_HOST/PORT/DB/PASSWORD 입니다. DSN 으로 받는 설정은 Alembic 용 ALEMBIC_DATABASE_URL 하나입니다.
  • Redis 는 6.2 이상이어야 기동합니다(refresh 회전의 GETDEL).
  • 프록시 뒤라면 TRUSTED_PROXY_HOPS 를 앞단 프록시 단 수로, CORS_ALLOW_ORIGINS 를 실제 출처로 좁힙니다.
  • alembic upgrade head 를 먼저 적용합니다(DEBUG=false 는 테이블을 만들지 않음). 첫 슈퍼유저는 python -m scripts.create_superuser 로 만듭니다.
  • 관리 화면을 쓰지 않으면 ADMIN_DISABLED=true, 쓰면 HTTPS 로만 접속합니다.
  • Celery worker 와 beat 한 개를 띄웁니다(beat 가 없으면 접속 로그 보존 삭제가 돌지 않음).
  • 컨테이너 종료 유예를 종료 정리 시간(lifespan 정리 최대 약 22초, listener 정지까지 약 29초 — 단계별 제한의 합이며 SHUTDOWN_TOTAL_TIMEOUT_SECONDS=20 은 강제되지 않음)보다 길게 둡니다.

빠뜨렸을 때의 결과까지 적힌 정본은 README 운영 배포 체크리스트 입니다.

관측과 장애 대응

  • liveness 는 /health(외부 연결을 보지 않음), readiness 는 /ready(writer DB SELECT 1·Redis PING, 각 2초) 입니다.
  • 접속 로그와 앱 로그는 경로·메서드·시각·user_id 로 맞춰 봅니다. 접속 로그에는 client IP·UA·상태 코드·소요 시간이 남습니다.
  • Redis 연결 오류: 기동 중이면 기동 실패. 운영 중이면 Redis 를 쓰는 요청(로그인·가입 레이트 리밋, refresh·logout, 사용자 비활성화·강등·삭제의 폐기, /admin, /ready)이 503 이고 서버 로그에 [RedisUnavailable] 가 남습니다. Redis 를 쓰지 않는 조회는 그대로 응답합니다. 우회해 허용하지 않습니다(fail-closed).
  • DB 장애: /ready 503, DB 를 쓰는 API 는 500. 접속 로그 저장 실패는 응답에 영향을 주지 않습니다.
  • 알림 대상: 5xx 증가, /ready 실패, [RedisUnavailable], 종료 timeout 로그([shutdown] … timeout).
